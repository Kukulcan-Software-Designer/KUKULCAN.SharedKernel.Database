# Domain Events

## Purpose

The database layer dispatches pending domain events after a successful
save.

## Flow

``` mermaid
flowchart LR
    A["Aggregate"] --> E["DomainEvents"]
    E --> S["Successful SaveChanges"]
    S --> I["DomainEventDispatchInterceptor"]
    I --> D["IDomainEventDispatcher"]
```

## Why Dispatch from Persistence?

Aggregates may be modified through different application paths.

Dispatching from the persistence boundary gives the system a central
integration point for events generated by tracked aggregates.

## Why an Abstraction?

The database library depends on `IDomainEventDispatcher`, not on a
concrete messaging framework.

This follows dependency inversion and avoids forcing a particular
mediator or message bus onto every consumer.

## Ordering

Events are collected from tracked `IHasDomainEvents` aggregates.

The events are then:

1.  copied;
2.  cleared from their aggregates;
3.  dispatched sequentially.

## No Outbox

The current project does not implement an outbox pattern.

Therefore, dispatch reliability across process boundaries remains a
responsibility of the consuming application architecture.
